# 3. Design Patterns

**Nível:** IMPORTANTE  
**Independência:** ✅ Os 23 padrões GoF são independentes de linguagem

## Objetivo
Reconhecer o problema que cada padrão resolve e quando aplicá-lo, em vez de apenas memorizar implementações.

## Conhecimentos Principais

### Criacionais
- Factory e Abstract Factory
- Builder
- Singleton (e seus riscos)
- Prototype

### Estruturais
- Adapter
- Bridge
- Composite
- Decorator
- Facade
- Proxy

### Comportamentais
- Chain of Responsibility
- Command
- Iterator
- Observer
- State
- Strategy
- Template Method
- Visitor
- Mediator

### Como usar
- Entender o problema e o contexto antes de escolher o padrão
- Na prática, poucos padrões (cerca de cinco ou seis) resolvem a maior parte dos casos
- Preferir a solução mais simples; um padrão não é objetivo, é meio

## O que NÃO Inclui
- Implementações em uma linguagem específica
- Variações próprias de uma biblioteca ou framework

## Por quê é Universal
Os padrões descrevem soluções para problemas recorrentes de design e não dependem de sintaxe.

## Referências
- Design Patterns - Gang of Four (1994)
- Martin Fowler - Refactoring
