# `node_modules/` — dependências Node

## Para que serve

Pasta gerada pelo `npm install` **neste clone** (desenvolvimento / testes do CLI). Contém pacotes Node baixados (ex.: deps transitivas de ferramentas de teste ou utilitários).

## O que **não** é

| Mito | Realidade |
|------|-----------|
| “O Jarvis roda em cima do que está em node_modules do framework” | O produto do Jarvis são **Markdown + CLI**. Assets (agents/skills/…) não dependem de `node_modules` no workspace do cliente |
| “Preciso copiar node_modules para a IDE” | `jarvis init` **não** copia `node_modules` |
| “Faz parte do pacote publicado” | Em geral **não** se publica `node_modules`; o install do usuário resolve deps do `package.json` |

## No dia a dia

- Clone limpo: `npm install` na raiz do framework se for desenvolver o CLI ou rodar testes.
- Workspace do squad: só precisa do pacote `jarvis-framework` (global, link ou `--save-dev`) — o `node_modules` do **workspace** é o do produto, não o desta pasta.

## Git

Normalmente `node_modules/` está no `.gitignore` de projetos Node. Se aparecer no seu clone local, não trate como fonte de verdade do framework.
